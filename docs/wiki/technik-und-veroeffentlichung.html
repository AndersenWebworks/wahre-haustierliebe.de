Technik und Veröffentlichung

Stand 9. Oktober 2026, am Code geprüft

Die Website ist eine statische Seite ohne Server und ohne Datenbank. Ein Node-Skript baut aus einer großen HTML-Quelle alle Einzelseiten, und GitHub Pages liefert sie unter wahre-haustierliebe.de aus. Veröffentlicht wird durch einen Push auf main. Dabei gelangt nur ein ausgewählter Teil des Repos ins Netz: Quellen, Werkzeuge und docs/ mit diesem Wiki bleiben privat.

Ein Push auf main ist eine Veröffentlichung. Der Workflow startet bei jedem Push automatisch. Es gibt keine Vorschau-Umgebung dazwischen.

Build

  1. node tools/build-static-pages.mjs baut alle Seiten und Nebendateien.
  2. Der Build rendert die Seiten mit Playwright vor, damit Hero, Tabellenlabels und andere per JavaScript verstärkte Bereiche schon im HTML stehen. Playwright kommt nicht aus diesem Repo: tools/playwright-module.mjs sucht es unter ../ClautzGPT/node_modules/playwright. Ohne ClautzGPT daneben läuft der Build nicht.
  3. Social-Vorschaubilder (1200 × 630) kommen aus den echten Seitenbildern; Startseite und Seiten ohne eigenes Bild nutzen das Logo.
  4. Danach die Audits laut README.md (static-pages-audit, layout-consistency-audit, image-layout-audit, article-context-audit, startpage-image-context-audit). Screenshots landen im ignorierten screenshots/.

Es gibt keine package.json im Repo. Im GitHub-Workflow wird nicht gebaut: Die generierten Dateien müssen gebaut und committet sein, bevor gepusht wird.

Quelle: README.md, tools/playwright-module.mjs, .github/workflows/pages.yml

GitHub Pages

Workflow .github/workflows/pages.yml („Deploy GitHub Pages“) läuft bei jedem Push auf main und manuell (workflow_dispatch). Schritte:

  1. Node 22 einrichten.
  2. node --check für Generator, Artefakt-Skript und Audit, danach node tools/static-pages-audit.mjs. Scheitert das Audit, wird nicht veröffentlicht.
  3. node tools/prepare-pages-artifact.mjs stellt das öffentliche Artefakt in .pages-artifact/ zusammen.
  4. Upload und Deploy über actions/upload-pages-artifact@v3 und actions/deploy-pages@v4.

Die eigene Domain steht in CNAME. Live liefert GitHub.com als Server aus.

Quelle: .github/workflows/pages.yml, CNAME; Kopfzeilen von https://wahre-haustierliebe.de/ am 9. Oktober 2026

Das Artefakt-Skript veröffentlicht nur freigegebene Pfade

tools/prepare-pages-artifact.mjs löscht .pages-artifact/, legt es neu an und kopiert nur zwei Arten von Pfaden hinein:

  • eine feste Liste: ai, assets, llms-full.txt, llms.txt, pwa, robots.txt, site.webmanifest, sitemap.xml, CNAME;
  • jede Seite aus ai/pages.json als …/index.html.

Vorher vergleicht es ai/pages.json mit sitemap.xml und bricht ab, wenn eine Seite nur in einer der beiden Listen steht. Jeder Pfad wird darauf geprüft, dass er nicht aus Projekt- oder Artefaktordner herausführt. Am Ende prüft es, dass jede Seite im Artefakt existiert.

Neue Seiten kommen damit automatisch mit, sobald sie in ai/pages.json stehen; eine zweite Deploy-Liste gibt es nicht.

Quelle: tools/prepare-pages-artifact.mjs (fixedPublicPaths, getPagePublicPaths(), copyPublicPath())

URLs, Metadaten und Maschinenlesbarkeit

  • Canonicals, Sitemap und interne Links nutzen bewusst slug/index.html statt slug/, weil ein früherer Tailnet-Server Verzeichnisse nicht als Index auslieferte. GitHub Pages kann beides; die Schreibweise bleibt aber einheitlich.
  • Jede Seite hat eigenen Titel, Beschreibung, Canonical, og:url, genau ein H1 und ein main, JSON-LD, Open-Graph- und X-Card-Tags.
  • Kein pauschales publisher: Organization und keine FAQPage-Auszeichnung ohne sichtbaren FAQ-Block (siehe Entscheidungen).
  • robots.txt erlaubt allen Crawlern einschließlich KI-Suchbots die Seite und sperrt nur /pwa/ (robotsDisallow im Generator).
  • lastmod steht je Seite im Generator. Fehlt der Eintrag, gilt process.env.SEO_LASTMOD oder fest 2026-08-25; am 9. Oktober 2026 tragen 64 von 77 Sitemap-Einträgen dieses Datum.

Quelle: README.md (Abschnitte „Aktueller Stand“, „GEO/SEO/AVO“), robots.txt, tools/build-static-pages.mjs (Zeile mit const lastmod), Auszählung von sitemap.xml

Kontakt und Hinweise ohne Server

Kontaktformular und Hinweisfunktion bauen per JavaScript einen mailto:-Entwurf an mail@andersen-webworks.de. Es gibt keinen Mailversand, keine SMTP-Zugangsdaten im Repo und keinen externen Formdienst, also auch keine Versandbestätigung.
